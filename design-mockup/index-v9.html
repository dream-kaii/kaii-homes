差别不在「模型更聪明」，而在外面这套工程：检索、工具、编排、上下文、留痕。
下面这些环节，就是我理解的、一个能真正跑起来的 Agent 应用要补上的东西。

LANDSCAPE

一个 Agent 应用要做好哪些事

一个能上线的 Agent，不只是「调个模型」这么简单。左边是它要听懂的部分，右边是它要答对的部分，中间是这句话真正走过的一遍。

输入侧 · 怎么听懂

多轮上下文

历史不是全量塞进去。最近几轮保真原文，更早的压成摘要，按 token 预算兜底。

滑窗滚动摘要

指代消解

「它能退吗」必须结合历史补全成完整问句，否则检索和意图都会判错。

corefquery rewrite

意图分流

退款要走确定性子流程，闲聊不该进 Agent，投诉要有固定兜底话术。

intentrouting

Query 扩写

一句问题泛化成几条侧重点不同的查询，多路检索后再去重合并。

multi-query

请求在系统里走一遍

从一句话进来到一句话出去，中间要过的关卡。

01
进来先补全

结合摘要与滑窗，把指代补成完整问句。

02
判意图定路线

八类意图带置信度，拿不准归「其他」。

03
知识类必先检索

该检索就检索（RAG），写成流程硬约束，而不是指望模型自觉。

04
过证据置信度闸

精排分、有效证据数、分差共同决定能不能答。

05
进 Agent 做决策

ReAct 循环临场决定调哪个工具、走几步收敛。

06
执行引擎统一把关

参数校验、权限分级、写操作等确认。

07
带引用生成

说出来源编号，答不了就如实拒答。

08
落 trace 与审计

每个节点的 prompt、耗时、token 都留痕。

名词速查

看不明白的词，这里有一句话解释
LLM
大语言模型。就是 GPT、DeepSeek 这类「会说话」的模型本体，只负责理解和生成文字，本身够不到你的数据库。
Agent
在模型外面套一层「能动手」的框架：它自己判断该做什么、去调工具拿数据、再根据结果决定下一步，直到把事办完。
Function Calling
让模型能「点菜」。你把可用的功能描述给它，它自己决定什么时候调用哪一个、传什么参数。
RAG
检索增强生成。回答前先去知识库里查相关资料，把查到的内容一起交给模型 —— 这样它才答得出模型没学过的私有信息。
向量检索
按「意思」而不按「字面」找资料。你问「邮费」，它能找到标题写着「运费怎么算」的那条。
重排 / Rerank
先粗筛出一批候选，再用更精细的模型重新排序，把最相关的排到最前面。快和准分两步做。
上下文
模型这一次能「看到」的全部文字。它有长度上限，聊得越久越容易超，所以要裁剪和压缩。
SSE
服务器推送事件。让回答一个字一个字冒出来，而不是等全部算完才一次性显示。
LangGraph
把 Agent 的流程画成一张图：哪些步骤有固定顺序、哪里需要模型临场决定，一目了然，也更好调试。
MCP
让 Agent 接外部工具的一套通用协议。别的系统按这个协议暴露能力，Agent 就能直接拿来用。
拒答
证据不足时明确说「我不知道」，而不是编一个听起来合理的答案。在生产环境里，这比答错更安全。
数据飞轮
把用户问倒的问题收集起来，人审后补进知识库 —— 系统用得越多，答得上来的就越多。
