01这个项目做了什么

MewHelp 是一个面向电商场景的智能客服系统。用户在聊天页问一句，后端会判断他到底想问什么， 决定要不要去查订单、检索知识库、或者走退款流程，最后把结果组织成人话回答出来。

整个项目是按章节逐步长出来的，不分支、不推倒重来。第一章只有一条对话接口， 到第十章收尾时已经是完整的一套东西 —— 这也是我觉得它比「一次写完的玩具项目」更有价值的地方： 每一章都在解决上一章暴露出来的真实问题。

03我解决过的工程问题

这一节是我觉得最有价值的部分 —— 它们不是「功能做完了」，而是「这东西真的能跑起来」。

上下文裁剪把工具调用链拆散，导致之后每一轮请求都失败

CRITICAL
问题
多轮对话要按 token 预算裁剪历史，原实现按「一问一答」成对删除。
后果
一旦对话里有工具调用，这个假设就不成立 —— 窗口会把 assistant(tool_calls) 和对应的 tool 消息拆开。超限后窗口以 tool 行开头，被上游拒收，之后每一轮都报错。
定位
来自最终全流程评审。根因是设计文档里写了「复用上一章的裁剪逻辑」，但那一章没有工具调用，成对裁剪在工具结构下不成立。
方案
升级为分组感知裁剪：一个组 = user，或 user + assistant(tool_calls) + tool… + assistant。保证窗口必然以 user 开头，当前轮永不删除。
验证
补 8 个边界用例，全量测试通过，重启服务实测多轮链路正常。

工具超时取消不了同步调用，写操作被重试了两次

IMPORTANT
问题
工具执行引擎统一做了超时加重试。但 asyncio.wait_for 只能取消协程，取消不了跑在线程里的同步工具。
后果
超时触发重试后，一个已经执行过的写操作会被再执行一遍 —— 静默的数据重复，日志里看不出异常。
方案
引入构建期的 non_retryable 黑名单，把有副作用的工具排除在重试之外。读操作照旧重试，写操作绝不。
取舍
为什么不直接对所有工具都不重试？因为读操作超时重试是安全的，放弃重试会明显降低成功率。

嵌入模型每轮请求重建，每轮重载几 GB 权重

IMPORTANT
问题
检索链路里，嵌入模型是在每次请求时构造的。
后果
权重加载一次约十几秒，而且向量库连接会随对象一起泄漏。第一个知识类问题会直接超时失败。
方案
改为进程级复用嵌入模型与向量库连接，并引入延迟连接的包装。同时把冷启动时阻塞事件循环的同步计算挪到线程池。
验证
用真实嵌入模型加向量库跑端到端冒烟，换说法的问句稳定命中。

测试替身把 bug 藏起来了

IMPORTANT
问题
模块重构后，一个调用方用的还是已被删掉的旧方法名，但我把测试里的替身对象写得比真实实现更宽容，所以测试全绿。
后果
测试通过，但线上路径一调就崩。这是最难发现的一类问题 —— 你以为有测试保护，实际上测试保护的是错的接口。
方案
把替身对象重建为镜像真实实现的接口面，返回类型也要一致。测试的价值在于复刻真实约束，不是模拟一个更好说话的世界。

04一段关键实现

工具执行的第一阶段：跨 chunk 合并工具调用，并对无法解析的调用主动失败。

tool_runner.py 复制 
async def stream_first_round(model_with_tools, messages, on_delta):
    """第一阶段：流式收集工具调用，同时逐 chunk 回调文本。"""
    acc = None
    parts = []
    async for chunk in model_with_tools.astream(messages):
        acc = chunk if acc is None else acc + chunk   # 跨 chunk 合并
        text = _text_of(chunk)
        if text:
            parts.append(text); on_delta(text)

    calls   = getattr(acc, "tool_calls", None) or []
    invalid = getattr(acc, "invalid_tool_calls", None) or []

    # 工具调用 JSON 无法解析时，处理不当本轮会静默无输出
    if not calls and invalid:
        raise ValueError(f"工具调用 JSON 无法解析：{invalid}")

    return normalize(calls), "".join(parts)

05已知限制

主动写清楚边界，比声称「完美」更接近工程现实。

  • 关键词降级路径对同义表达仍会漏召回 —— 这正是引入混合检索的直接原因，但降级路径本身保持原样未升级。
  • user_id 目前没有鉴权，会话归属只按 id 过滤。这是课程项目的简化设计，不是生产形态。
  • 会话级并发锁覆盖了同一 session 的写冲突，但没有做跨实例的分布式协调。
  • 嵌入与重排模型绑定本机缓存路径，换环境需要重新下载权重或改配置。
